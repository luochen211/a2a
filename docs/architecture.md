# 架构设计

本文描述待实现的目标，不代表已交付能力。

## 两个边界

内部任务层负责需求、审批、依赖调度、执行记录与产物验收；协议层负责 Agent Card 发现、消息发送、远端任务状态、取消及产物传输。

优先基于官方 SDK 实现协议层。只有需要对外提供 Agent 服务时，才增加 A2A Server；仅调用远端 Agent 的场景可以先实现 Client。

## 任务与产物

内部任务、每次执行尝试、远端任务分别保留独立标识及映射。不得假定不同远端服务的任务 ID 可以互用。

建议让批准的任务版本、执行尝试、固定产物与验收报告相互关联。任务变更后重新判断审批与既有验收是否仍然有效。

远端 `completed` 映射到内部待验收阶段。验收失败记录证据并决定是否重试；验收通过才进入交付阶段。取消、失败及需要补充输入应独立处理。

## 第一阶段验收目标

- 客户端能够发现 Agent Card，并与独立服务端完成消息或任务交互。
- 明确处理直接 Message 响应和 Task 响应。
- 记录远端地址、任务标识及产物，确保能追溯到内部执行。
- 用失败与取消场景验证状态变化；明确所选 SDK 和服务支持的能力。
- 根据需要选择流式返回或轮询，不要求所有服务实现每个可选能力。

协议与 SDK 的版本必须一起固定。协议兼容性测试通过和业务产物验收通过分别报告。
